# 论文规律的合成 trace 验证

当前生成器可以用人工配置接近部分边际统计：头部 client 请求份额、多轮请求份额、会话平均请求数和小时级突发贡献。它尚未复现论文的完整联合分布。Web 是配置入口；生成质量以实际导出 trace 的统计为依据。


## 参考口径

- [ServeGen](https://www.usenix.org/system/files/nsdi26-xiang-servegen.pdf)：§3.3 的 M-small 在 48 小时内有 2,412 个 client，前 29 个贡献约 90% 请求；§5.2 的 deepseek-r1 在 12 小时内约 10% 请求属于识别出的多轮对话，报告平均 3.5 轮，轮间到达间隔集中在约 100 秒附近并有长尾。两组属于不同工作负载，不合成一个“统一生产目标”。
- [FineServe](https://arxiv.org/html/2607.19349v1)：§3.1 在 300 秒窗口内统计每秒请求数的 CV、MSSD，并比较相邻窗口的 KS、W1；Fig.4 中最忙 5% 秒的小时请求贡献随类别和时段变化，部分 Dense 时段达到 15–18%。§3.2/Table 3 还给出输入与输出的条件关系：Dense 输出在中等输入附近达到峰值，然后下降。

ServeGen 的到达间隔 CV 与 FineServe 的每秒计数 CV 是不同统计量。配置的 `arrival.cv` 只控制单个 client 的 session 发起间隔，两个论文口径都必须在 serving 请求合并后重新测量。

## 方法与参数来源

[8 组配置](../examples/paper_patterns/)均由配置独立生成，不读取参考数据集，不执行搜索、拟合或自动校准。每组使用 seed 41、42、43，保存真实含 `hash_ids` 的压缩 trace、完整 manifest 和逐窗口统计，共 24 次生成。误差范围为三个 seed 的最小值到最大值，不是置信区间。

配置中的注释注明来源与假设：client 数和参照份额来自上述论文；指数、绝对请求率、离散轮数分布形状、轮间 lognormal 尾部以及 token 长度均为人工补充。这里选较低流量以控制实验成本，不能据此声称匹配生产规模或其他依赖强度的统计。

- 头部份额：48 小时，2,412 个配置 client、0.25 sessions/s，每 session 一条请求，隔离 client 分配效果。按实测请求数重新排序选前 29 个。
- 多轮：12 小时，0.5 sessions/s；单轮与多轮为两个任务。多轮请求数为 `[2,3,4,6]`，概率为 `[0.3,0.3,0.2,0.2]`，期望 3.5。到达间隔用 log-space σ=1.2、众数 100 秒的 lognormal；这不是均值或中位数 100 秒。
- 到达：1 小时、基准 10 sessions/s，每 session 一条请求。比较 Poisson、周期阶梯增强、Gamma CV=3，并检查 client 数量变化的聚合效果。阶梯增强为每 180 秒最后 9 秒从 10 提升至 32 sessions/s，平均强度也随之升高。
- 所有时窗为 `[0, duration)`，初始没有历史 session；窗口末尾不排空。多轮份额按实际看到至少两条请求的 session 计算，并另存按生成器计划识别的份额。完整 session 的平均轮数与所有 session 的计划轮数分别报告。

## 实测结果

下表为三个 seed 的均值；方括号为范围。

| 指标 | 对照配置 | 调整后实测 | 参照与判断 |
|---|---:|---:|---|
| 前 29 个 client 请求占比 | 均匀权重：2.01% | 权重指数 1.6：91.09% [91.01%, 91.20%] | 接近约 90%，高 1.09 个百分点 |
| 识别出的多轮请求占比 | 10% session 分给多轮：26.85% | 3.08% session 分给多轮：9.73% [9.56%, 9.85%] | 接近约 10% |
| 完整多轮 session 平均请求数 | — | 3.487 [3.426, 3.530] | 接近报告的 3.5；不是完整 CDF 验证 |
| 每小时最忙 5% 秒的请求贡献 | Poisson：8.53% | 单 client、Gamma CV=3：16.43% [16.19%, 16.83%] | 落入部分时段的 15–18% 范围 |
| 同一突发贡献指标 | 同上 | 周期阶梯增强：14.60% [14.39%, 14.83%] | 已增强，但仍略低于该范围 |

多轮 session 权重按份额的期望关系手工换算。设目标请求份额为 q，多轮平均请求数为 m，其他 session 均为单轮，则 `p = q / (m(1-q)+q)`。q=0.1、m=3.5 时 p≈0.03077。该式不补偿冷启动和尾部截断，因此实测值可以偏离 10%。调整后每次有 25–42 个 session 被截断；计划平均请求数为 3.522，完整会话均值为 3.487。

不能把上述匹配项扩展成其他指标也匹配：

- 头部配置只观察到 815–834 个有请求的 client，未达到论文的 2,412 个活跃 client。低流量下尾部来源大量未发起请求，配置人口不等于观测人口。
- 多轮间隔实测中位数约 408 秒、P95 约 2,798 秒；100 秒是人工选择的分布众数。论文未给这些分位数的精确数值，本实验不把它们判为“已匹配”。论文同时报告的请求数/会话数之比约为 3.304，与正文平均 3.5 不完全一致，故不将两者同时作为精确约束。
- 8 组配置独立检验不同规律，没有一组同时满足全部参照。单轮到达实验尤其不能证明真实 Agent 多轮负载的时序和上下文增长已经复现。

## 聚合后的 CV 与统计差异

保持总发起强度 10 sessions/s、每个 client 的 Gamma 间隔 CV=3，只改变 client 数量：

| serving 侧实测量（三 seed 均值） | 1 个 client | 64 个 client |
|---|---:|---:|
| 全小时请求间隔 CV | 3.001 | 1.818 |
| 300 秒窗口计数 CV 的均值 | 0.878 | 0.631 |
| 300 秒窗口 MSSD 的均值 | 141.09 | 69.88 |
| 最忙 5% 秒的小时请求贡献 | 16.43% | 13.06% |

因此，单独调 `arrival.cv` 并不能固定最终请求流的 burst。client 分配、多轮续发和总体强度都必须一起统计；相同配置 CV 也不意味着相同的计数 CV。不同强度下 Poisson 自身的计数 CV 也会变化，不能用这些数值直接给不同生产模型排名。

## 当前表达缺口

1. **输入–输出条件分布。** 当前一个 task 内的 `output_tokens` 独立采样，不依赖当前输入长度。它不能在同一 profile 内表达先升后降或增长后饱和的条件中位数。混合多个 profile 可以构造粗略的聚合形状，但不能当作任务内条件模型已实现。
2. **细粒度到达聚集。** 当前使用连续 renewal 时钟，没有 FineServe 的毫秒计数 NB 机制。统计脚本输出包含空槽的毫秒 Fano 值，但未将其与论文表格数值强行对齐；时间分辨率、零槽处理和绝对强度需要先一致。
3. **分布尾部与联合规律。** 当前没有原生 Pareto、条件 gap–growth 关联、上下文压缩或 Agent 分支。已有离散/长尾分布和 session seed 能提供轮数及增长多样性，但缺乏同口径的生产新增上下文统计验证。

这些是生成逻辑的边界，不由 UI 曲线是否平滑判断。现有结果支持继续使用配置驱动生成；不支持“已经接近全部 paper 统计”或“可以代表近期 Agent 生产流量”的结论。

## 复现与统计定义

在仓库根目录运行：

```bash
python3 experiments/validate_paper_patterns.py
# 可选绘图，需安装 experiments/requirements-plot.txt 中的依赖
python3 experiments/plot_paper_patterns.py
```

默认写入 `runs/paper-patterns/<配置名>/<seed>/`：`trace.jsonl.gz`、对应 manifest、`statistics.json`；完整汇总为 `runs/paper-patterns/results.json`。每次统计包含 trace 的 SHA256，便于核对重跑。实验数据与生成图片仅保留在本地，不纳入版本控制。

统计全部来自导出的请求行。计数包含空秒；CV 使用总体标准差除以均值。IAT 只在相邻请求都属于同一个 300 秒窗口时计入该窗口。MSSD 除以 299，不跨窗口；相邻计数窗口的 KS 正确处理重复值，W1 是两组各 300 个有序样本的绝对差均值。每个完整小时选计数最高的 180 秒计算贡献。零请求窗口的 CV 和零请求小时的贡献为 null。另保存长度、新增上下文、轮间间隔的样本数、均值、CV、P50/P95/P99。

统计口径由手工可计算的样本测试覆盖，包括空秒、重复计数、跨窗口 IAT、KS/W1 和毫秒空槽。全套 Python 17 项测试通过；功能测试不替代上面的统计比较。
