# 配置驱动的 Client Pool 与多轮请求合成设计

本文定义 traceGen 的重构方案，功能实现状态以代码和 README 为准。

## 1. 目标

根据整体配置和任务行为配置生成 LLM serving 接收的请求流，表达流量组成、波峰波谷、burst、多轮时序、上下文增长与前缀复用。

生成过程不依赖 Weka、LMSYS 等数据集的 session 模板采样。论文提供负载规律和参考配置参数，不引入自动校准或迭代拟合。前缀使用合成身份，无需真实文本、tokenizer 或生产 block hash。

```text
整体配置 + 任务行为配置
          ↓
     Client Pool
          ↓
  Client 发起 session
          ↓
  Session 生成多轮请求
          ↓
   按到达时间合并请求
          ↓
请求 trace + 配置快照 + 统计图表
```

## 2. 对象模型

| 对象 | 职责 | 配置或状态 |
|---|---|---|
| Task profile | 定义一类任务的共同规律 | 轮数、间隔、长度和共享分布 |
| Client | 持续存在的请求来源，代表用户或上游应用 | 任务类型、稳定身份、流量权重、活跃规律 |
| Session | 承载一次多轮过程 | session seed、轮数、历史、前缀身份、相对时序 |
| Request | 表示一次 LLM 调用 | 到达时间、输入/输出长度、前缀关系 |

每个 client 使用一个 task profile，同类任务可以有多个异质 client，一个 client 可以发起多个 session。人类一次交互可能包含多次 LLM 调用；human turn 与 request index 分别命名。

Client pool 采用 ServeGen 的分来源生成、按时间聚合方式，并在 client 下显式维护 session。不同 client 的活跃变化同时影响服务端请求频率与请求属性组成。

## 3. 整体流量

### 3.1 发起强度与组成

整体配置控制新 session 发起强度，单位为 `sessions/s`。服务端请求率是多轮展开后的统计结果，单位为 `requests/s`，不作为另一个需要自动满足的硬目标。

设整体基础发起强度为 S(t)，任务混合权重为 p_k(t)，任务内 client 权重为 w_i(t)：

```text
任务 k 中 client i 的基础 session 发起强度
  = S(t) × p_k(t) / sum(p(t)) × w_i(t) / sum(w_in_task_k(t))
```

任务混合权重表示 session 发起的相对贡献。client 数量占比、session 占比和最终请求占比分别展示。轮数差异、续发延迟和时间窗口会使最终请求组成不同于 session 组成。

### 3.2 波峰波谷与 burst

整体强度曲线由控制点或周期参数定义。任务和 client 可以配置活跃时段、相位与局部 burst。

全局 burst 作用于总体发起强度，局部 burst 作用于指定来源的发起强度。局部增强不自动削减其他来源；需要保持总量并改变组成时，编辑归一化的任务/client 权重。

Client 的 `activity` 为分配后的局部倍率，不参与权重归一化；停用 client 的份额不补给其他 client。具体字段及计算顺序见[配置协议](configuration.md)。连续曲线按固定时间网格及拐点划段，以中点强度进行数值近似；该网格属于生成参数，不是图表窗口。

已有 session 按自身时序继续执行。波谷不切断 session，burst 不压缩轮间间隔。最终请求曲线可以相对 session 发起曲线滞后并产生拖尾。

### 3.3 轮间时间

直接采样相邻 LLM 请求的到达间隔，并可按人类触发和工具触发使用不同分布。该间隔包含两次到达之间的全部时间，不再叠加响应耗时。

`session.gap` 支持多个连续分布的加权混合，每次使用 session 的 timing RNG 选择分量并采样，以表达短调用间隔与长恢复停顿的边缘分布。分量不是已识别的用户/工具状态，不自动保证停顿的序列相关性。参考数据的离线参数估计与运行时生成分离，生成器只读取固定配置。

工具/用户等待时间不能直接代替到达间隔。基础生成器不模拟 serving 执行反馈，论文参数必须按相同时间口径使用。

可选 `session.max_context_tokens` 限制单次请求的总输入上下文。若下一轮累计输入将超过上限，session 提前结束；首轮已经超限时报错。不截断历史或改写前缀，抽样请求数与限制后计划请求数分别记录。

## 4. Session 多样性与可复现性

### 4.1 两级随机采样

Task profile 定义分布，每个 session 独立采样，生成不同的轮数和上下文增长轨迹。

| 层级 | 采样项 | 作用 |
|---|---|---|
| Session 级 | 请求轮数、初始私有上下文、增长倍率 | 决定整段会话的长短和增长规模 |
| Request 级 | 外部新增上下文、模型输出、到达间隔 | 决定会话内逐轮波动 |

增长倍率每个 session 只采一次，应用于该会话各轮外部新增上下文，使整段任务可以持续偏大或偏小。倍率固定为 1 时，仅保留逐轮波动。

分布参数决定多样性和波动幅度，seed 决定具体抽样结果。

### 4.2 Session seed

每个 session 使用独立、稳定的随机种子：

```text
session_seed = stable_hash(
    global_seed, task_key, client_key, client_local_session_ordinal, "session-v1"
)
```

使用明确编码和稳定哈希算法，不使用 Python 进程随机化的 `hash()`。session 序号来自 client 自身的候选发起顺序，在准入等待前确定，不使用到达时间或聚合后的全局编号。

Session seed 派生四个子流：

- `structure`：轮数、初始私有长度、增长倍率和公共前缀组选取。
- `growth`：每轮外部新增上下文。
- `output`：每轮模型输出长度。
- `timing`：会话内到达间隔。

Client 的 session 发起时钟使用独立随机流。会话内增加采样不会改变后续 session 的发起时间；长度采样的随机数消耗不会意外改变时间采样。

在同一生成器版本、相同 profile、session seed 和共享组配置下，生成相同的会话结构、长度及相对时序。绝对开始时间由外部流量决定。修改流量或截止窗口可以改变输出 session 集合与截断结果，但对应稳定身份的会话随机实现不变。

生成侧 session 元数据记录 seed 和稳定身份，便于定位与重放，不在每条请求中重复保存 seed。

## 5. 上下文与前缀生成

### 5.1 线性多轮过程

1. 选择公共前缀组，取得该组的长度和身份。
2. 使用 session seed 采样轮数、初始私有上下文和增长倍率。
3. 生成本轮输入前缀，采样模型输出长度并输出请求。
4. 采样下一轮到达间隔和外部新增上下文。
5. 将前轮模型输出与外部新增内容加入历史，继续下一轮，直到结束。

对于保留完整历史的会话：

```text
L[s, 0] = public_prefix_length[s] + initial_private_length[s]
L[s, k] = L[s, k-1] + output_length[s, k-1]
          + integer_tokens(growth_multiplier[s] × external_new_length[s, k])
完整 block 数 = floor(L[s, k] / block_size)
```

外部新增上下文只包含工具结果或用户输入等新内容，不包含前轮模型输出，避免重复累加。先累计整数 token，再对完整上下文划分 block，保留跨轮积累的不足一块部分。

### 5.2 身份规则

- 同一公共前缀组共享确定的长度与身份，不由各 session 独立重采样共享内容。
- Session 私有历史继承已有身份，新增内容生成新身份。
- 不同 session 的长度相同不表示内容相同，同一 profile 不会使完整会话重复。
- Block 身份体现此前完整前缀；不同父路径下的相同局部编号不表示共享。
- 输出 `hash_ids` 表示完整合成 block 的前缀身份，数量由输入长度和 block 粒度推导。
- 前缀长度不超过输入长度；历史可复用比例不等于有限缓存命中率。

## 6. 配置参数

| 配置层 | 参数 |
|---|---|
| 运行范围 | 时长、全局 seed、合成 block 粒度 |
| 总体流量 | Session 基础发起强度、时间控制点、插值、周期、峰谷倍率、相位 |
| Burst | 起始时间、持续时间、倍率或增量、上升/下降时间、作用范围 |
| 任务组成 | Task profile、session 混合权重及其时间变化 |
| Client pool | 每类 client 数量、稳定标识、流量权重与头部集中度 |
| Client 活跃规律 | 活跃时段、相位偏移、局部 burst |
| Session 发起 | 到达分布及参数 |
| Session 结构 | 请求轮数分布 |
| Session 随机性 | 从全局 seed 和稳定身份派生 session seed 及子流 |
| 轮间时间 | 相邻请求到达间隔分布、触发类型 |
| 初始上下文 | 公共前缀组长度、初始私有长度分布 |
| 逐轮增长 | Session 增长倍率、每轮外部新增长度分布、输出长度分布 |
| 前缀共享 | 组数量、组热度、共享范围 |
| 输出 | 请求字段、配置快照、session 元数据 |
| 图表 | 统计窗口、平滑、对数轴、来源筛选、前后对比 |

分布控件按类型显示参数，例如固定值、Gamma、Lognormal、离散分布。每种分布明确单位和参数化方式，不将相互决定的均值、CV、shape、scale 同时作为独立输入。

## 7. 参考配置

论文用于提供规律与参考参数。每个预设注明定性依据、原文统计的观测范围及单位，以及为构成可运行场景补充的假设。人工参数不得标成实测结果，边缘统计不能当作已经观测到的联合分布。

| 预设 | 表达的规律 |
|---|---|
| 交互式 Chat | 人类轮间等待、多轮历史增长 |
| Coding Agent | 工具驱动连续请求、短间隔、持续上下文增长 |
| 长任务 Agent | 更多轮次、较长上下文、间歇性长等待 |
| 头部 Client 主导 | 少数 client 贡献主要流量，活跃变化带动请求属性变化 |
| 日周期混合 | 多任务随时间形成波峰波谷 |
| 突发混合 | 特定来源增强，已有会话继续产生请求 |

参考文献：

- [ServeGen](https://www.usenix.org/system/files/nsdi26-xiang-servegen.pdf)：client 分解、异质性、流量与请求属性变化。[ClientPool 实现](https://github.com/alibaba/ServeGen/blob/d70c8b2/servegen/clientpool.py)。
- [FineServe](https://arxiv.org/abs/2607.19349)：不同模型/任务的到达与长度特征。
- [SMetric](https://arxiv.org/abs/2607.08565)：Agent serving 的 session、复用来源和时间关系。
- [Agentic Coding in the Wild](https://arxiv.org/abs/2608.00101)：生产 Agent 的轮次、间隔、压缩与用户异质性。
- [TraceLab](https://arxiv.org/abs/2606.30560)：日常 coding agent 的工具、人类停顿和上下文增长。
- [A Year in LLM Serving](https://arxiv.org/abs/2608.13573)：聚合流量、用户—模型组成与长期变化。

客户端/产品遥测用于解释 session 内行为，serving 日志用于解释聚合入口；不将客户端样本直接视作完整服务端流量。实际缓存读取 token 数不等于内容公共前缀长度。

## 8. 交互与图表

### 8.1 图表

请求到达是离散事件，窗口 RPS 为窗口请求数除以窗口秒数。支持切换 1 秒、10 秒、1 分钟等观察尺度。

| 图表 | 横轴 → 纵轴 | 用途 |
|---|---|---|
| 估算 running requests | 并发值或时间 → 时间加权分布或窗口平均并发 | 按每请求 50/80/100 token/s，忽略 prefill 和排队；报告串行依赖冲突 |
| Session 发起强度 | 时间 → sessions/s | 编辑输入曲线 |
| 服务端总到达率 | 时间 → requests/s | 展示多轮展开结果 |
| 任务流量堆叠 | 时间 → 各任务 RPS | 查看波峰组成 |
| Client 流量 | 时间 → 各 client RPS | 查看头部贡献 |
| Burst 局部放大 | 时间 → 多窗口 RPS | 区分尖峰与趋势 |
| 服务端 IAT 分布 | 请求间隔 → CDF | 查看聚合离散程度 |
| 窗口计数自相关 | 滞后 → 相关系数 | 查看高低负载持续性 |
| 活跃 session | 时间 → 数量、首请求率 | 查看会话累积与续发 |
| Session 规模 | 请求数/持续时间 → CDF | 查看长会话尾部 |
| Session 内间隔 | 到达间隔 → CDF | 查看会话时序 |
| 上下文增长 | 请求序号 → 长度分位数 | 查看不同会话的增长差异 |
| 请求长度分布 | 输入/输出/外部新增 tokens → CDF | 查看属性与长尾 |
| 前缀复用 | 比例/复用间隔 → CDF | 查看共享程度和重访速度 |
| 属性随时间变化 | 时间 → 长度分位数、token/s | 查看流量与内容组成联动 |
| 时间—长度联合图 | 间隔 → 新增长度，二维密度 | 查看两者关系 |

活跃 session 按首次至末次请求到达定义，不等于正在执行的推理请求数。单请求 session 的活跃持续时间为零。高轮次的上下文分位数仅统计到达该轮的 session。

### 8.2 编辑与预览

- 拖动整体强度、任务权重和 burst 控制点。
- 用滑块或数值框调整 client 数量、分布参数、轮数和长度。
- 分布编辑器显示独立抽样的 CDF 和抽样 PDF/概率质量，反映 clip 和整数化后的分布。
- 拖动时更新输入曲线，松开后生成短 trace 并刷新统计结果。
- 固定 seed，叠加调整前后的输出；观察窗口和平滑只影响显示。
- 导出完整配置、请求 trace 和统计摘要。

结果曲线用于理解配置影响与检查约束，不要求贴合论文曲线。多个 seed 可以展示随机波动范围。

## 9. 实现范围与验证

基础生成核心实现任务 profile、client pool、session 发起时钟、session 独立随机流、线性多轮、合成前缀、时间合并和可复现输出。命令行与交互界面使用同一份配置语义和生成核心。

当前实现包含 version 3 配置协议、生成核心、六组人工预设、CLI、JSON 统计、PNG/SVG 曲线与交互编辑工作台。工作台支持参数控件、曲线和 burst 拖拽、task/client 筛选、统计窗口、平滑、对数轴、局部放大、固定基线叠加及导出。旧数据集生成、转换与校准代码及其脚本已删除，所有入口使用同一个合成核心。

压缩、分叉、重试、human turn 层级、复杂 client 活跃状态、并发准入以及 serving 运行时反馈不属于基础版本。

生成质量通过配置生成真实 trace 后的同口径统计验证，Web 作为辅助配置工具。[论文规律验证](paper-pattern-validation.md)包含 8 组配置、3 个 seed 的实测结果。头部份额、多轮份额和部分突发贡献可接近论文参照；当前 task 内独立输出采样无法表达输入–输出条件曲线，新增上下文与到达的联合分布也尚未完成生产统计验证。局部统计接近不代表全部工作负载复现。

关键验证项：

- 同一版本、配置与 seed 可复现。
- 对应稳定身份的 session 不因配置排列或无关来源新增而改变随机实现。
- 会话内随机数消耗不改变发起时钟。
- 公共前缀共享、私有历史隔离、完整 block 身份正确。
- 长度核算不重复计入输出，不丢失跨轮不足一个 block 的部分。
- Burst 不隐式改变已有 session 的轮间规则。
- 时间顺序与输出窗口边界处理一致。
- 图表设置不改变底层 trace。
