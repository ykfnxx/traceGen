# daily_mixed 的会话内间隔混合分布

所有任务的 `session.gap` 使用连续 Lognormal 混合。先按权重选择分量，再从该分量采样；`mean` 是算术均值（秒），不是固定间隔，所有 CV 都大于零。没有 min/max 裁剪，避免概率质量堆积在边界。每个 session 使用独立 timing 随机流，每轮重新采样；目前没有阶段持续时间、状态转移或 session 级节奏倍率。

间隔口径是相邻 LLM 请求的到达时间差，已包含两次到达之间的全部时间，不额外叠加推理或工具耗时。混合分量可以重叠，不是互斥时间段，也不是经过识别的用户/工具状态。多种行为支持采用混合模型，但不证明每类任务都有三个可辨认的峰。

## 80 token/s 的时间尺度约束

输出量定义为同 session 的 `next.input_tokens - current.input_tokens`，不扣除外部新增字段。按该输出量除以 80 估算耗时，超过相邻到达间隔即记为重叠。没有下一请求的末次已输出请求不参与此口径分析。配置中的旧独立 output_tokens 参数仍参与上下文增量构造，分析不直接使用该字段作为输出量；本次只调整间隔，未改动 token 生成器。

离线使用 seed 43/44/45、每任务每 seed 2000 个完整计划 session，计算 `新增量 / (80 × 原间隔)` 的 P90，向上取到 0.1，并取至少 1，作为所有分量 mean 的共同倍率。目标为参考样本约 10% 重叠，并用独立 seed=42 的完整 trace 验证接近 90% 不重叠。不裁剪间隔，不固定到达时间，不保证每个 session 无冲突；不包含 prefill 或排队。配置运行时不再调参。

倍率（相对未缩放参考分布）：Chat 1、Coding 2.5、QA 19.1、客服 2、Research 13.3、Data analysis 8.9。该调整是速度约束场景，不是原始数据分布复现。长间隔会增加会话存活和窗口外请求数量。

## Chat 的公开数据拟合

来源：[ServeGen conversations_hashed.json](https://github.com/alibaba/ServeGen/blob/main/data/conversations/conversations_hashed.json)，Git blob SHA `a8cc92632d01a9e0a8a8a42d9f22f86bdd74f9f0`，2026-09-15 获取。共 1616 个会话，按文件内各会话顺序计算相邻 `timestamp` 差，得到 4104 个有限正间隔，无非正样本。它是选择性公开的多轮子集，不能代表全部生产流量或普通聊天用户。

对 log(gap) 使用 EM 比较 1/2/3 个高斯分量，转换为 Lognormal 算术均值和 CV。使用现有离线 Weka 拟合实验相同的初始化、最多 300 次迭代及 seed=42 的 20 万抽样 KS 评估；按候选模型 BIC 选择三分量，未做独立测试集或多初始化验证。

样本 P50/P90/P95/P99 为 308.32/3229.38/8595.50/22650.55 秒，样本均值 1618.87 秒；三分量期望 1637.35 秒。这个子集比原人工 chat 慢很多，也不能直接等同于论文中更大样本的图。长间隔将增加跨窗口裁剪；不将它们压缩到一天内。

## 其他任务的参考规律与限制

- [AgentSysBench §7.3（2026-08）](https://arxiv.org/html/2608.15127v1#S7.SS3)：生产 search-QA 的搜索工具均值 1.349 秒、P90 1.708 秒。它只是工具耗时，不能直接作为完整 gap；也不足以确定 QA 长等待占比。
- [Applied Compute（2026-04）](https://www.appliedcompute.com/research/inference-benchmark)：code QA、coding、office 负载的工具延迟通常约一秒，尾部可超过数百秒；其统计口径是模型响应完成到下一请求，而非两次请求到达。用来支持快慢时间尺度共存，不把 office 等同于客服或数据分析。
- [τ-knowledge（2026）](https://taubench.com/blog/tau-knowledge.html)：客服涉及文档检索、工具发现和条件化用户交互。模拟用户无法提供真人回复等待分布；客服混合权重尚无生产统计支持。
- [Deep Research performance study（2025）](https://cseweb.ucsd.edu/~yiying/2025_NIPS_ERW_Deep_Research_Perf_Study.pdf)：搜索与生成阶段、长短任务耗时不同。整任务耗时不等于某次 gap，不能除以平均调用数后当作实测间隔分布。
- [Agentic AI Workload Characteristics §6（2026-05）](https://arxiv.org/html/2605.26297v1#S6)：ADE 的轻量文件操作、Bash 和委派任务耗时不同，例如表 1 中 Qwen Thinking 的 Bash 均值 1.27 秒、Agent 66.31 秒。工具类别数量不等于 LLM 请求数量；只据此提供数据分析多时间尺度的参考场景，不直接换算权重。

## 检查口径

分别检查独立 gap 样本、完整计划 session 的 gap 和时间窗口内实际输出的 gap。报告 P50/P90/P95/P99、超过 60/300/3600 秒的比例、各 session 持续时间及窗口裁剪数量。前两者与后者不同，窗口通常少观察到长间隔；测试通过只证明配置可运行、采样可复现，不证明四类人工配置贴合生产统计。
